# Website Content

Write the content the page needs, not generic "website copy."

## Establish the job

Before drafting, determine:

- the surface: page content, navigation, interface language, reference material, instructions, editorial writing, or marketing copy
- the primary page job and any secondary job
- the visitor's main questions, prior knowledge, and likely next step
- the facts, proof, source material, voice guidance, and product constraints available
- whether the request is to plan, draft, edit, or audit

Read [references/page-jobs.md](references/page-jobs.md) when the page job is not already explicit. For hybrid pages, name one primary job. Let the secondary job influence only the sections where it belongs.

Ask only for missing information that would materially change the result. Otherwise state a reasonable assumption and proceed. Never fill an evidence gap with an invented claim, number, quote, testimonial, credential, or urgency cue.

## Route to the right guidance

Always read [references/universal-standards.md](references/universal-standards.md).

Then read only the references needed for the current work:

- Inform, orient, or explore: [references/informational-content.md](references/informational-content.md)
- Teach or enable, including UI strings and flows: [references/ux-and-instructions.md](references/ux-and-instructions.md)
- Establish trust, persuade, or convert: [references/trust-and-persuasion.md](references/trust-and-persuasion.md)
- Search intent, titles, descriptions, or structured discoverability: [references/search-and-metadata.md](references/search-and-metadata.md)
- Audit or edit an existing draft: [references/audit.md](references/audit.md)

## Build the content

1. Write a one-sentence content brief: page, audience, primary job, and useful outcome.
2. List the visitor questions in the order they need answers. Turn that order into the page hierarchy.
3. Choose the content types each question requires. Do not use a marketing section where a label, definition, instruction, table, example, or source note would work better.
4. Draft from verified material. Put the answer or next action before background detail.
5. Apply the routed guidance, then run the audit in `references/audit.md` before delivery.

For edits, preserve accurate material, established terminology, and genuine voice. Change structure when the current order prevents understanding or task completion, and say what moved.

When explaining or auditing a writing problem, do not stop at a bad example or an abstract recommendation. Show a concrete improved alternative grounded in the available facts, or use clearly marked placeholders when the necessary evidence is missing.

## Deliver useful work

Match the output to the request. A full page may need a content brief, hierarchy, draft, and open evidence questions. A button label may need only the label and one sentence of context. An audit should lead with prioritized findings rather than burying them under a rewrite.

Separate publishable content from commentary. Clearly label assumptions, missing evidence, and claims that need verification.
